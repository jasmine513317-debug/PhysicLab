## 4. 目标架构边界

### 4.1 实验核心

`ExperimentCore` 只持有权威状态：场景、维度、物理模式、时间、事件队列、初始快照、求解器配置、随机种子、采样配置和相机快照。UI、Canvas、WebGL 和 Worker 通过命令与观察结果访问它，不直接修改求解器内部对象。

### 4.2 求解器接口

- `RigidBodySolver`：先封装 Planck 二维刚体。
- `ContinuousDynamicsSolver`：轨道、连续场运动与自定义积分。
- `ElectromagnetismSolver`：静电场、洛伦兹力、RC 瞬态、感应。
- `AstrophysicsSolver`：二体、三体、引力助推等经过验证的模型。
- 三维求解器在独立阶段评估，不将三维刚体引擎与科学场模型混为一个不可解释的黑盒。

所有求解器使用内部 SI；天文展示换算必须在边界显式进行。外层固定步为 1/60 s，求解器可声明自己的子步和积分器。

### 4.3 渲染与交互

- 二维继续使用 Canvas2D；三维按门槛评估 Three.js 或兼容渲染器。
- 坐标模块负责 world/display/screen 双向转换；原点移动只改变测量基准。
- 指针、触控和键盘生成统一编辑命令；操作是否可撤销由实验核心决定。
- 物理时间与渲染时间分离；后台标签页不得补算数小时模拟。

### 4.4 观测与事件

- 求解器采样和图表采样是不同通道，分别有界。
- 实时轨迹、预测轨迹和理论曲线使用不同来源标记，预测不得写入真实历史。
- 所有运行时外力进入带模拟时间、对象、前后状态和模式的事件队列。
- 严格模式拒绝不可能操作；自由干预模式执行真实状态修改并记录守恒定律适用性警告。

## 5. 数据格式与迁移保护

| 数据 | 当前格式/位置 | 3.0 策略 |
| --- | --- | --- |
| 力学场景 | JSON `version: 1 | 2 | 3` | v1 无手绘/轨道；v2 支持手绘与轨道；v3 增加语义角色、场源电荷、识别来源与椭圆。保持旧语义，不强制升级。 |
| 力学回放 | 独立 Replay JSON 与 IndexedDB store | 保留历史场景快照；新增确定性事件与初始状态后升版本，不删除旧回放。 |
| 旧力学库 | `physiclab`，数据库版本 2 | 保持版本，避免旧版应用无法打开。 |
| Studio 力学库 | `physiclab-studio` / `physiclab-semantic`，数据库版本 1 | v2/v3 分域存储；读取最高有效版本，回放跟随场景版本，删除时清理同 ID 的全部力学副本。 |
| 静电/天文/扩展 | 三个独立 IndexedDB 域与各自 schema | 独立迁移，不将领域数据强塞进力学 schema。 |
| 几何导入 | 几何工作室自有数据 | 只导入通过校验的几何；保留来源与信息损失说明。 |

`src/model.ts` 的 `experimentDecoders` 是力学场景版本注册入口。未知或缺失版本在解析前拒绝，不猜测、不补默认值、不修改源记录。`tests/versioning.test.ts` 覆盖 v1/v2/v3 保真、未来版本拒绝和缺失版本拒绝；`tests/repository.test.ts` 覆盖同 ID 跨版本选择、损坏记录回退、回放关联和删除。

迁移规则：

1. 文件版本、求解器模型版本、回放版本和 IndexedDB 数据库版本分别管理。
2. 先复制/适配，再验证；验证失败不覆盖原始记录。
3. 有损转换必须保留原快照与信息损失说明。
4. 数据库升级前验证备份、失败重试、多标签页和回滚。
5. 2D→3D 暂停后映射；3D→2D 仅平面状态可无损，否则投影/剖切/取消并保留快照。

## 6. 物理与测试风险

- 数值积分、接触、摩擦、弹簧和轨道模型必须绑定明确假设、初始条件和参考解。
- 近零真值使用绝对/混合误差；不得用相对误差制造 `NaN` 或虚假精度。
- 《任务书》初始阈值为：简单力学主要量 ≤0.1%，弹性碰撞动量 ≤0.1%、动能 ≤0.5%，保守振动能量漂移 ≤0.5%，二体轨道能量/角动量漂移 ≤0.1%。阈值只在对应测试条件下有效。
- 高频弹簧、高速碰撞、端点接缝、多接触、无重力、关闭碰撞和物体超范围是必测边界。
- 不支持的模型或范围必须返回可读错误，不能输出 `NaN`/`Infinity` 或静默降级。
- 3D 模板、性能数字和“已验证”标签只能来自实际测试，不能来自静态演示。
