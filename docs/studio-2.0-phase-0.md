# PhysicLab Studio 2.0 · Phase 0 项目审计

审计基线为 `main` 提交 `8cca1dd`。本文记录 1.x 当前实现、升级前需要处理的问题，以及多领域数据上线后的回滚路径。

## 现有结构与可复用功能

| 模块 | 现有能力 | 2.0 衔接点 |
| --- | --- | --- |
| 首页与实验库 | 首页 `/`、工作台 `/lab`、实验库 `/experiments`。支持创建、打开、重命名、复制、删除和导入场景 JSON。 | 保留旧路径、查询参数和模板标识。新增入口同时检查 GitHub Pages 子路径与 Vercel 直达路由。 |
| 工作台 | `Lab.tsx` 管理编辑、运行和回放。`Viewport.tsx` 与 `Inspector.tsx` 支持选择、拖拽、旋转、缩放、平移、参数编辑和触控。已有运行、暂停、单步、重置、倍速和快捷键。 | 提取跨领域共用的工作台框架，现有力学编辑和运行流程继续通过原入口使用。当前深蓝配色可在 Phase 1 迁移到规划中的黑白配色。 |
| 几何与物理 | `drawing.ts` 识别手绘草稿并生成直线、斜面及凸多边形等现有形状。`model.ts` 校验圆、矩形、静态表面和 3 至 8 顶点凸多边形。`physics.ts` 使用 Planck，以 60 Hz 固定推进、15 Hz 采样。 | 保留 Planck 和现有刚体形状。可视曲线使用单独的几何模型，验证并离散后再生成静态碰撞边界。曲线约束运动另行实现。 |
| 模板 | 已有自由落体、斜抛、斜面摩擦、弹性碰撞和弹簧振子。 | 保留五个模板。电偶极子、电势和双体轨道需在求解器、参考解和容差测试就绪后发布。 |
| 可视化与数据 | Canvas 2D 画布显示轨迹和矢量。底部支持位置、速度、加速度、能量曲线，单次基准对比、抛体理论指标、CSV 导出及历史回放。 | 保留既有力学图表和导出字段。扩展时为每个观测量提供量纲、单位和数据来源。新增动量、轨道和场图层前建立各自的参考测试。 |
| 持久化 | IndexedDB 保存场景和独立回放，每个实验最多一份持久化回放。场景可移植为 JSON，运行数据可导出为 CSV。 | 保持旧实验 ID、初始条件、视角、时间戳及历史回放。增加完整备份与恢复验证。 |

当前力学边界包括 100 个刚体、200 个弹簧，以及约四分钟的逐物体回放窗口。清单见 [已知限制](known-limitations.md)。自由曲线编辑、函数曲线、三维曲面、电磁学、天体物理和多次实验分析是规划中的新增能力。

## 基线问题与影响

| 发现 | 影响与处理时机 |
| --- | --- |
| 基线的 README 与部署指南写 Node.js ≥22.12，npm 锁文件内 Planck 1.5.1 与 stage-js 1.0.2 的 `engines.node` 均要求 ≥24。 | 已将本地和部署说明统一为 Node 24，与现有 Pages 流程一致。 |
| `listExperiments()` 对所有记录直接调用 `decodeExperiment()`。任一损坏或未来版本记录抛错时，整批查询失败。 | 新领域接入前隔离单条解析失败，在库中保留可读记录，并提供失败记录的恢复路径。 |
| `AnalysisPanel.tsx` 的抛体轨迹均方根误差用理论飞行时间筛选样本，再以至少 1 为分母。回放窗口滚动到飞行结束以后，且仍有至少两个总样本时，空样本集可显示为 `0.000 m`。 | 先以实际参与对比的样本数判断是否有结果。后续误差分析覆盖录制窗口滚动、发生接触和参考模型失效的情况。此项来自代码检查。 |
| `App.tsx` 的场景导入只读取 v1 场景，`Lab.tsx` 的 JSON 导出只包含场景。 | 现有 CSV 可带走观测值，但无法恢复完整回放的场景快照、角度等信息。迁移前补齐回放备份和恢复。 |
| 生产构建对 Zod 4.6.7 报两条 Rollup `@__PURE__` 注解位置警告，构建成功。 | 依赖更新时复查生产输出，当前锁定版本可继续作为基线。 |

## 数据迁移计划

1. Phase 1 保持现有场景 `version: 1`、回放 `version: 1` 和 `physiclab` 数据库版本 2。数据库早期版本只有 `experiments`，现有升级路径会增加 `replays` 并保留场景。`tests/completion.test.ts` 已覆盖该路径。
2. 2.0 在读取边界引入版本化的领域模型。将 v1 场景在内存中适配为力学实验，保留 ID、实验模板类型、时间、环境、相机、所有刚体和弹簧，以及旧实验默认行为。回放继续从自己的历史场景快照和采样轨道读取。实验文件格式、求解器模型版本和数据库版本分别管理。
3. 新领域使用独立的 2.0 存储命名空间。库列表合并可读记录，并按来源路由加载、重命名、复制和删除操作。同 ID 的升级副本应有明确优先级。旧格式仍可表示的力学编辑继续写回旧库；首次保存旧格式无法表示的几何或参数时，生成关联的 2.0 副本，保留原始记录。新写入在事务完成后更新界面。
4. 发布新存储前，先完成场景与回放一并备份和恢复。旧 v1 JSON 仍可导入，沿用为导入副本分配新 ID 的行为。完整备份恢复若重新分配 ID，应同时重映射场景、回放及其关联；未知版本的原始数据应可保全并给出可读错误。CSV 继续用于图表数据交换。
5. 迁移验收覆盖 v1 JSON、旧版本数据库、共享页面同源升级、重复打开、失败重试、多标签页、混合版本记录、相同 ID 冲突、旧实验及回放重开，以及完整备份恢复。使用旧运行样本核对回放，使用相同初始条件核对力学计算。

## 回滚方案

1. 发布前保留 `8cca1dd` 的生产构建及部署配置，升级后的发布继续沿用同一站点来源。Pages 产物使用实际项目路径作为 Vite `base`，保留 `/lab` 和 `/experiments` 的直达与刷新能力。
2. 工作台或求解器出现阻断问题时，重新部署上一版稳定产物。因为旧数据库保持版本 2，上一版仍可打开旧场景、回放及兼容写入的力学编辑。留在 2.0 存储中的新增实验和升级副本由兼容版本重新部署后读取。
3. 若后续要提升旧数据库版本，先发布能打开新版本数据库的兼容构建，并将该构建作为回滚目标。直接回退到请求数据库版本 2 的原版应用会收到 `VersionError`。回滚过程中保留浏览器存储和备份，避免清站点数据。
4. 在同一测试来源提前演练升级、写入、回退、再升级。逐项打开旧实验和旧回放，恢复新实验并核对记录数量、ID、时间戳和初始条件。

## 验证结果

- `pnpm run build` 通过。Vite 输出入口脚本约 117 kB gzip，按需加载的工作台脚本约 134 kB gzip，Planck 脚本约 45 kB gzip。这些是单文件体积基线。
- Vitest 全部 26 项通过。覆盖自由落体、抛体、碰撞、接触摩擦、弹簧周期、固定时间步、采样、场景校验和旧实验库升级。现有物理容差见 [科学与软件验证](testing.md)。
- Playwright 在 Microsoft Edge 对生产包运行，全部 19 项通过。覆盖回放存取、JSON 导入导出、重力预设、键盘操作、触控模拟和 50 刚体场景。本次浏览器复测覆盖 Edge 与移动触控模拟。
- GitHub Pages 产物检查通过。以 `/PhysicLab/` 为资源路径构建，确认 `lab/index.html` 和 `experiments/index.html` 均已生成。此项为本地产物检查。
